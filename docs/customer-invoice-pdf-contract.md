# Customer invoice PDF — proposed implementation contract

## Scope
One commercial invoice per order after verified payment, independent of fulfillment. Unpaid orders retain payment instructions, not a paid invoice. Original paid invoice remains unchanged on refund; a separate credit/refund note is a future extension. Not a Faktur Pajak. Confirm legal seller identity, tax treatment, and historic seller details before production; do not invent them.

## Existing audit (2026-11-28)
Order and OrderItem already snapshot customer, product/variant, quantity, price, line total, subtotal, discount/voucher, shipping, currency, grand total. PaymentTransaction records provider, reference, amount, type, status and timestamps. PaymentService.ApplyNotificationAsync commits verified Paid and fulfillment startup under order lock. GET /api/v1/me/orders/{id} is authenticated and owner scoped. No invoice table or service found. Existing SkiaSharp 3.119.1 and Linux native assets can render with SKDocument.CreatePdf (https://learn.microsoft.com/en-us/dotnet/api/skiasharp.skdocument.createpdf?view=skiasharp-3.119); verify font embedding, Unicode, multi-page Linux rendering. DEV has two paid orders with PaidAt. No new PDF service required.

## DB and backend
Add order_invoices with Id UUID, OrderId unique FK, InvoiceNumber unique (INV-{existing unique order number}, proposed), PaymentTransactionId FK, IssuedAt UTC, PaidAt UTC, SnapshotJson JSONB versioned, TemplateVersion, GenerationStatus Pending/Ready/Failed, AttemptCount, LastAttemptAt, NextAttemptAt, PdfSha256 and bounded PDF bytea for MVP (private, included in DB backups; move to private object storage later if volume warrants). Snapshot seller name/address/contact, necessary buyer name/email, order items, totals, payment reference/method if supported by verified evidence. Never include passwords, OTP, game credentials, QR payload, redeemable vouchers or unnecessary personal details. Original snapshot and final PDF bytes immutable.
Create invoice issuance row in same transaction as first verified Paid transition using common service and unique constraints; audit all paid entry points. A bounded retryable worker renders after commit; PDF failure never reverts payment or blocks fulfillment. Prevent duplicate generation on concurrent webhook/reconciliation, retries and backfill. Backfill existing paid orders with audited dry run and verified seller/payment evidence; preserve original PaidAt, use actual issue time. Flag discrepancies for review; no invented payment method. Refund preserves original invoice and records refund separately. Additive migration, backup before DEV release.
A4 PDF: branded header, invoice number/date, order reference, paid date, seller/buyer, item table (name/variant/qty/unit/line total), subtotal, discounts, shipping, total and currency, verified payment details, paid label. Wrap long items, repeat table headers, include page number; local fonts/assets only, no remote HTML/URL. Use exact decimal amounts, reconcile line totals and successful payment; UTC persisted, Asia/Jakarta displayed.

## API
GET /api/v1/me/orders/{id} adds invoice { number, status, issuedAt, available } or null. GET /api/v1/me/orders/{id}/invoice returns application/pdf with attachment filename; validate authenticated order ownership every time, 404 for other users, private no-store; 409 preparing or 503 generation failure. No public URL. CMS authorized download/retry with audit logging. Guest access separate future scope; order number alone never authorizes download.

## Frontend
Invoice card near payment totals on owned order detail, number/date and Download PDF. Paid + Processing must still allow invoice. Preparing/failed states show clear feedback and refresh; never pretend a file exists. Authenticated fetch, validate response, blob download/revoke, localized copy and responsive UI. CMS status and retry.

## QA/release
Confirm seller legal identity/address/contact, tax policy, historical seller evidence, numbering and guest scope. Then migration + snapshot issuance + worker, ownership endpoint and frontend/CMS. Test replay and concurrent issue, missed webhook, worker failure/retry, immutable prices, exact amounts, multi-page, Unicode, no secrets in PDF/logs, unauthorized user, refund and paid-before-fulfillment. Back up DEV DB, deploy backend, dry-run verified backfill, deploy frontend, run actual Midtrans sandbox settlement + PDF download. PROD separate approval. No invoice code or migration in this planning branch.
